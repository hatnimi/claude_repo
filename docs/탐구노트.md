- 직접 들어 본 결과: ( )
- 문제의 구조: TTS 입력은 **글자**뿐이다. 장단은 글자에 드러나지 않고 **의미**에 따라 정해진다.

## 2. 배경 지식
- **표준 발음법 제6항**: 모음의 장단을 구별하여 발음하되, 단어의 첫음절에서만 긴소리가 나타난다.
  - 눈보라[눈ː보라] / 첫눈[천눈], 말씨[말ː씨] / 거짓말[거ː진말]
  - 그래서 코드에서 **형태소가 어절 첫머리일 때만** 장음을 적용했다 (`morph.py`의 `word_initial`).
- **현실의 한계**: 현대 서울말 화자, 특히 젊은 세대는 장단을 거의 구별하지 않는다는 연구가 많다.
  → "표준 발음을 지키는 TTS"와 "자연스럽게 들리는 TTS"가 다를 수 있다. 이 탐구의 목표는 표준 발음 쪽이다.
- **VITS 구조**: 텍스트 인코더 → **duration predictor**(토큰마다 몇 프레임 낼지) → 정렬 → flow → HiFi-GAN 디코더.
  장단은 결국 '몇 프레임'의 문제이므로 duration predictor의 출력이 개입하기 좋은 지점이다.

### 3-3. 상용 TTS에 적용
- SSML `<prosody rate="55%">눈</prosody>이`: 장음 음절만 느리게 읽힌다.
- SSML을 지원하지 않는 TTS(gTTS)는 철자를 바꾼다: 눈 → 누운.
  이중모음은 뒤쪽 단모음을 늘린다: 과(ㅘ=ㅗ+ㅏ) → 과아.
- 관찰: 실제로 길게 들렸나? 부자연스러운 점은? ( )

## 4. 방법 2: VITS 텐서에 직접 개입
### 4-1. 아이디어
```python
def hook(module, inputs, output):          # output = log_duration, 모양 (1, 1, 토큰 수)
    return output + log_w                  # 장음 모음 토큰 위치만 log(w), 나머지는 0
model.duration_predictor.register_forward_hook(hook)
```
- **왜 log 공간에서 더하나?** 모델이 `duration = ceil(exp(log_duration))`로 계산한다.
  `exp(a + log w) = w · exp(a)`이므로 더하기 한 번이 곱하기 w가 된다.
- **왜 speaking_rate를 쓰지 않았나?** speaking_rate는 문장 전체 속도를 바꾼다. 우리는 모음 하나만 늘려야 한다.
- **왜 blank 토큰도 늘렸나?** MMS 토크나이저는 글자 사이에 blank(`_`)를 끼운다(`_ n _ u _ n _`).
  모음 소리가 blank 쪽까지 이어지는 경우가 많아서 모음 토큰과 바로 뒤 blank를 같이 늘렸다.
  - 실험해 볼 것: 모음 토큰만 늘렸을 때와 비교 ( )
- **공정한 비교**: VITS의 duration predictor는 난수를 쓴다. 그래서 기본 음성과 수정 음성을 같은 seed로 생성했다.
- **입력이 로마자인 이유**: `mms-tts-kor`는 한글을 uroman으로 로마자화한 입력으로 학습됐다.
  그래서 한 음절씩 로마자로 바꾸면서 "이 로마자 글자는 몇 번째 한글 음절에서 왔는지"를 기록해 두었다(`romanize`).

## 5. 멜 스펙트로그램 비교
- 멜 스펙트로그램: 가로축은 시간, 세로축은 사람 귀의 감도에 맞춘 주파수(멜 척도), 색은 에너지.
- 무엇을 봐야 하나: 장음 음절 구간(하늘색)에서 모음의 **포먼트 띠**(가로 줄무늬)가 옆으로 더 길게 이어지는가.
- **VITS**: duration을 알기 때문에 음절 구간을 정확히 표시할 수 있다.
- **상용 TTS**: 정렬 정보가 없다. 그래서 DTW로 두 음성을 맞춰 "기본 음성의 각 순간이 몇 배로 늘어났는지"를 그렸다.
  - DTW 검증: 합성 신호에서 한 구간만 2배로 늘렸을 때 그 구간의 평균 배율은 2.07, 나머지는 0.98이었다.
  - 주의: 소리가 일정한 구간 안에서는 DTW가 늘어난 위치를 정확히 짚지 못하고 한쪽에 몰아서 표시한다.
    그래서 곡선의 모양보다 **구간 평균**으로 해석해야 한다.

## 7. 한계와 후속 탐구
- 사전에 있는 단어만 처리한다 → 표준국어대사전 전체에서 장단음 동음이의어를 자동으로 추출할 수 있을까?
- 용언의 장단(감ː다/감다, 묻ː다/묻다)과 활용 시 단음화(감ː다 → 감아[가마])는 다루지 못했다.
- 길이만 바꿨다. 실제 장음에는 음높이나 강세 변화가 함께 나타날 수 있다.
- 평가가 내 귀와 구간 길이뿐이다 → 여러 사람에게 들려주고 "어느 쪽이 雪으로 들리나" 청취 실험을 할 수 있다.
- 근본적인 해결: 장단 표시(ː)를 입력에 넣은 데이터로 TTS를 학습시키는 방법.
